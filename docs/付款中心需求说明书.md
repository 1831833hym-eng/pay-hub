## 2. 需求说明

### 2.1 背景

跨境付款申请在飞书审批中完成，出款、复核、回单回传缺少统一工作台。付款中心承接已通过的审批信息，生成付款单，完成初审、复核、出款与回单，并支持全量查询与付款单 / 审批单比对。

### 2.2 目标

| 编号 | 目标 | 衡量标准 |
| --- | --- | --- |
| G1 | 统一承接审批单并生成付款单 | 付款单含审批单编号、名称、金额、收款信息 |
| G2 | 按环节分岗处理 | 初审、复核、查询、比对四个菜单，数据范围互不串单 |
| G3 | 出款后闭环 | 复核通过进入待付款；付款成功后待回单；回单回传飞书后已完成 |
| G4 | 作废可追溯 | 作废为逻辑删除；查询可看，初审列表不可见 |

### 2.3 范围

| 类型 | 说明 |
| --- | --- |
| 范围内 | 四个菜单；列表查询、合计、分页；明细基础信息 / 收款账户 / 处理历史；初审、单笔作废、复核确认 / 退回；比对结果 |
| 范围外 | 真实飞书 / 万里汇联调、登录鉴权、账务核销、回单文件归档、权限中心 |

### 2.4 角色

| 角色 | 职责 | 主要操作 |
| --- | --- | --- |
| 初审岗 | 核对付款单并提交复核 | 查询、初审、修改转账附言、单笔作废、重新同步 |
| 复核岗 | 确认出款或退回 | 选择付款渠道、确认、退回 |
| 查询岗 | 只读查看全部单据 | 按条件与状态查询、看明细 |
| 对账岗 | 核对付款单与审批单 | 查询比对结果 |
| 系统 / 渠道 | 出款与回单 | 万里汇付款、回单回传飞书 |

### 2.5 术语

| 术语 | 定义 |
| --- | --- |
| 付款单 | 承接审批信息后在付款中心生成的出款单据 |
| 审批单 | 飞书审批流单据，编号默认写入转账附言 |
| 初审 | 将待初审单据提交至待复核；明细底栏按钮文案为【提交复核】 |
| 作废 | 将待初审单据状态改为已作废，不物理删除 |
| 比对结果 | 付款单与审批单在金额、币种、收款人、收款账号上的一致 / 不一致 |
| 转账附言 | 出款附言，默认等于审批单编号；仅初审编辑态可改 |

### 2.6 约束

| 类型 | 说明 |
| --- | --- |
| 假设 | 进入付款中心的审批单已在飞书审批通过 |
| 依赖 | 飞书审批、万里汇付款与回单（本期原型模拟） |
| 约束 | 作废不可物理删除；比对排除已作废；复核付款渠道必填，默认万里汇；明细只读字段不使用输入框；操作成功不使用页面顶部横幅 |

## 4. 实体设计

### 4.1 关系

一张付款单对应一张审批单。付款单拥有多条处理历史。出款交易号、回单号挂在付款单上。比对结果由付款单与审批单字段实时对照，不单独落库。

```text
审批单 1 ── 1 付款单
付款单 1 ── N 处理历史
付款单 1 ── 0..1 出款回单（万里汇交易号 / 回单号）
付款单 × 审批单 → 比对结果（计算，不落库）
```

## 5. 业务流程

### 5.1 主流程

1. 飞书审批通过，付款申请信息同步至付款中心。
2. 付款中心生成付款单，状态为待初审，转账附言默认等于审批单编号。
3. 初审岗在「初审付款单」核对，可修改转账附言，【提交复核】后进入待复核。
4. 复核岗选择付款渠道（默认万里汇），【确认】后进入待付款。
5. 系统调用万里汇（或所选渠道）出款；成功后写入交易号，状态为待回单。
6. 系统获取回单并回传飞书审批流，写入回单号，状态为已完成。

```text
                    【作废】
待初审 ──────────────────────────► 已作废
   │
   │【提交复核】
   ▼
待复核 ──【退回】──► 待初审
   │
   │【确认】（选择付款渠道）
   ▼
待付款
   │
   │【万里汇付款成功】
   ▼
待回单
   │
   │【获取回单并回传飞书】
   ▼
已完成
```

规则：

1. 待初审是接入态，也是复核退回后的回流态。界面名称不用「待提交」。
2. 已作废只从待初审进入，查询可见，初审 / 复核 / 比对不可见。
3. 待付款、待回单、已完成在本期原型以查询展示为主，出款与回单为模拟动作。
4. 每次初审、复核、作废都追加处理历史，不覆盖旧记录。

### 5.2 节点

| 步骤 | 角色 | 动作 | 系统处理 | 结果状态 |
| --- | --- | --- | --- | --- |
| 1 | 系统 | 承接飞书审批 | 生成付款单，附言默认审批单编号 | 待初审 |
| 2 | 初审岗 | 【提交复核】 | 保存转账附言；写处理历史「初审」 | 待复核 |
| 3 | 复核岗 | 【确认】 | 记录付款渠道；写处理历史「复核」 | 待付款 |
| 4 | 系统 | 出款成功 | 记万里汇交易号 | 待回单 |
| 5 | 系统 | 回单回传飞书 | 记回单号 | 已完成 |

### 5.3 分支

| 场景 | 触发 | 处理 | 结果 |
| --- | --- | --- | --- |
| 复核退回 | 复核岗【退回】 | 状态改待初审；历史记复核退回 | 回到初审列表 |
| 作废 | 初审行内【作废】并确认 | 状态改已作废，不删数据 | 初审列表消失，查询仍可见 |
| 重新同步 | 初审明细【重新同步】 | 刷新更新时间，不改状态 | 停留在初审明细 |
| 出款失败 | 渠道返回失败（后续联调） | 保持待付款 | 支持重试 / 重新同步 |
| 比对不一致 | 金额 / 币种 / 收款人 / 账号不同 | 结果列「不一致」，差异格标红 | 不改付款单状态 |
